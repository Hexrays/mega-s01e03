Separate fixes

  • Shared parser: day-first tenant input reaches a month-first shared parser through app, email, or a form without the booking-v3 hint defect. For example, Harbour Dental’s R-41200 says 7 April became 4 July. Read the tenant’s date order, not the browser’s. Fix the shared parser and test ambiguous and unambiguous dates in supported locales.
  • Form hint: booking-v3 prints MM/DD/YYYY, but its day-first tenant form reads the input day first. This affects form reports from Alder Physio, Copper Studio and Pale Harbour. For example, R-41230 reports 6 January becoming 1 June. Make the displayed hint agree with the form parser. A shared-parser fix alone does not correct misleading text.

Use tenant locale from the tenant directory and date order from Intl.DateTimeFormat. Use the report channel and the tenant’s form version. Intake tags are browser-based guesses. Do not count by subject, intake tag, browser locale, or the number of raw export rows.
